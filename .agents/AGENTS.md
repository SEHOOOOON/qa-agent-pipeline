# 깃헙 커밋 및 코드 수정 워크플로우 규칙

모든 작업 시 다음 규칙을 항상 준수하세요.

1. **수정 전후 비교 설명 (Before & After)**:
   - 코드나 문서를 수정하기 전에, 반드시 이전 내용(Before)과 수정 후 내용(After)을 비교하여 어떤 점이 달라지는지 사용자에게 먼저 명확히 설명해야 합니다.
2. **커밋 메시지 중복 방지**:
   - 깃헙 커밋 내용에 대화창에서 이미 설명한 내용을 그대로 중복해서 길게 적지 마세요.
3. **한글 커밋 작성**:
   - 깃헙에 커밋할 때 커밋 메시지는 반드시 한글로 작성합니다. (예: `feat: 실행 증거 메타데이터 추가 및 HTML 버그 수정`)
4. **계획서(Plan) 대화창 요약 출력**:
   - `implementation_plan.md` 등 계획서를 작성한 후에는, 사용자가 따로 파일을 열어보지 않아도 되도록 대화창에 계획서의 핵심 내용(수정 방향, 오픈 퀘스천 등)을 직접 마크다운으로 요약해서 보여주어야 합니다.
