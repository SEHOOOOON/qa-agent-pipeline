Multi-Agent QA Workflow

반복되는 회귀 테스트의 휴먼 에러를 줄이고, 사람은 더 복잡한 이슈를 찾는 데 집중하기 위해 자동화를 기획했습니다. 하지만 AI에게 온전히 맡길 경우 상황을 임의로 추측하여 신뢰도가 떨어지는 문제가 있었습니다. 이를 해결하기 위해, 제 실무 QA 기준을 체크포인트로 적용하여 AI가 항상 일관된 품질로 테스트를 수행하도록 구조화했습니다.

품질 기준 보기반려·수정 사례실행 증거

※ 시뮬레이터의 Agent·CI/CD 화면은 Workflow Demo이며, 실제 결과는 Pytest Report와 실행 결과 JSON을 기준으로 합니다.

1 프로젝트 배경

일관된 품질 판단 기준의 필요성

검토자의 경험에 따라 달라지는 테스트 범위와 AI가 근거 없는 기대값을 만드는 문제를 구조적으로 개선하고자 했습니다.

!

반복해서 마주한 문제

  • 동일 요구사항도 담당자에 따라 테스트 범위가 달라짐
  • AI가 요구사항에 없는 기대값을 확정함
  • 모호한 TC가 자동화와 보고 단계까지 전파됨
✓

프로젝트의 접근 방식

  • QA 판단 기준을 3단계 품질 기준으로 구조화
  • Agent가 정해진 형식으로 결과물을 생성
  • Checkpoint가 동일한 기준으로 결과 품질을 확인
핵심 목표AI가 많은 테스트케이스를 만드는 것이 아니라, 요구사항부터 실행 결과까지 동일한 품질 기준을 유지하고 근거 없는 판단이 다음 단계로 넘어가지 않도록 하는 것입니다.
2 전체 아키텍처

Agent와 QA Checkpoint 구조

왼쪽에는 각 Agent가 생성하는 결과를, 오른쪽에는 해당 결과를 확인하는 QA Checkpoint를 나란히 배치했습니다. 이후 섹션에서 요구사항 정제부터 결과 보고까지 실제 처리 순서를 설명합니다.

AGENT 02

AGENT 04

4-1 테스트케이스 설계 품질 기준

3단계 품질 기준을 적용한 TC 설계

Agent 2는 Agent 1이 전달한 확정 정보에 공통 QA 기준, 중앙제어 도메인 기준과 기능별 품질 기준을 차례로 적용해 테스트케이스를 작성합니다.

1단계

공통 QA 기준

모든 기능에 공통으로 적용하는 기본 검토 기준입니다.

  • 정상·예외·경계값
  • 상태 변경과 회귀 영향
  • 정보 부족 여부
2단계

중앙제어 도메인 기준

중앙제어 시스템에서 중요하게 다루는 위험을 확인합니다.

  • 모드별 제어 제한
  • 통신·알람·Lock 상태
  • 다중 장비와 상태값 일치
3단계

기능별 품질 기준

실제 테스트와 자동화에 필요한 판단 조건을 구체화합니다.

  • 적용 조건과 기대결과
  • 통과·실패 판단 기준
  • 자동화 가능 범위

9 프로젝트 가치

프로젝트를 통해 입증한 QA 가치

단순히 AI와 기술을 사용하는 것을 넘어, 이 프로젝트에서 실제로 확인한 QA 역량과 의미입니다.

QA 판단 기준의 구조화

경험에 머물던 QA 판단 기준을 공통 QA, 중앙제어 도메인, 기능별 품질 기준으로 구분하고 반복 적용할 수 있도록 정리했습니다.

AI 결과에 대한 품질 통제

AI가 만든 결과를 그대로 사용하지 않고 근거, 독립성, 판정 가능성과 추적성을 검토해 승인된 결과만 다음 단계로 전달했습니다.

실행 결과 기반 의사결정

자동화 상태와 실패 원인을 분리하고, Report와 결과 데이터의 정합성을 확인해 릴리즈 권고까지 연결했습니다.

핵심 의미AI를 많이 사용하는 것보다, 동일한 QA 기준이 요구사항부터 실행 결과와 보고까지 유지되도록 만드는 것이 이 프로젝트의 핵심입니다.

01

02

실행 증거 보완 중

03

AI 검토의 한계

AI가 만든 결과를 AI만으로 검토하지 않고 규칙 기반 검사와 실제 실행을 함께 사용해야 합니다.

04

호출 비용과 처리 시간

모든 Agent 분석을 매번 수행하면 실행 시간과 모델 호출 비용이 증가할 수 있습니다.
